# Как устроены обновления Foodastry

Коротко: **правим файлы → бета-сайт → смотрим → публикуем**.
Никакой ручной загрузки через браузер больше нет — всё делают два файла‑клика.

---

## Карта мира

| Что | Где |
|---|---|
| Рабочая папка (файлы сайта) | `C:\Users\Administrator\Downloads\KR` |
| Основной сайт | https://knclose.github.io/foodastry/ |
| Бета-сайт (черновик) | https://knclose.github.io/foodastry-beta/ |
| Основной репозиторий | github.com/knclose/foodastry (remote `origin`) |
| Бета-репозиторий | github.com/knclose/foodastry-beta (remote `beta`) |
| Облако данных | Supabase, проект `foodastry` |

## Ветки

- **`dev`** — рабочая ветка. Здесь правим файлы, здесь же живём постоянно.
- **`main`** — то, что стоит на основном сайте. Публикация = отправить туда `dev`.

Бета-сайт — это просто тот же репозиторий `dev`, отправленный в бета-репозиторий.

---

## Обычный цикл обновления

1. **Правим.** Вы просите изменить что-то — я меняю файлы папки `KR`
   и сохраняю в ветку `dev`.
2. **`beta.bat`** (двойной клик). Введите одной строкой, что изменилось
   (например: «добавила блюдо недели в шапку») → Enter.
   Через 30–60 секунд бета-сайт показывает обновление.
3. **Проверяем** на бете: дизайн, телефоны, счётчики.
4. Понравилось → **`release.bat`** (Enter = подтвердить). Основной сайт
   обновится через 30–60 секунд — с любого вашего устройства.
5. Не понравилось → говорите, что переделать, я правлю — снова `beta.bat`.
   Основной сайт при этом спокоен.

Мелкие очевидные правки (опечатка, новый текст) можно сразу
`release.bat` без беты.

## Что делает каждый скрипт (честно)

**`beta.bat`** = `git add -A` → `git commit -m "…"` → `git push beta dev:main`
(созрел коммит → уехал на бета-сайт).

**`release.bat`** = `git push origin dev:main` → основной сайта получил
новую версию; локальная ветка `main` догоняет `dev`.

## История и откат

Каждая публикация остаётся в истории навсегда (github.com →.commits).
Если публикация получилась неудачной, я откатываю сайт к любому старому
состоянию одной командой — просто скажите «откати вчерашнюю версию».

## Пара правил

- **Данные — не в Git.** Рецепты и ингредиенты живут в Supabase; правки
  закоммиченных файлов их никогда не трогают.
- **Бета-сайт смотрит в то же облако.** Переименование таблиц/полей в
  базе в бете отразится на основном сайте (общие данные). Если когда-нибудь
  понадобится менять структуру базы — сначала я подниму бете отдельный
  проект Supabase (10 минут), потом правим схему.
- **`config.js` несекретен.** Все ключи в нём — публичные «ключи-доступа
  к открытой таблице», так Supabase и задуман.
- Если бета-сайт «не поменялся» — почти всегда кэш браузера: **Ctrl+F5**.

## Если..(редкие случаи)

- **Опубликовали и передумали** → скажите «закати открутку», откачу.
- **Случайно удалился локальный файл** → я подскачу: `git checkout -- <файл>`
  вернёт из последнего коммита.
- **Бета-репозиторий просит что-то странное** → скажите мне, я разберусь
  (вероятно, нужно пересоздать одно из настроек).
